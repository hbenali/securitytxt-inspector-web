Why this page does not fetch it for you

A browser may only read another site's file if that site sends CORS headers. Tested in headless Chrome: github.com, google.com and cloudflare.com sent none, and hbenali.ovh redirects to a host that answers 404, so every request was blocked. Even where it could work, this page's strict Content Security Policy (connect-src 'none') cannot allow an arbitrary domain. So the fetch is done with curl, then you paste the output above.

Legacy location

The -i flag prints the response headers: RFC 9116 requires HTTPS and Content-Type: text/plain; charset=utf-8, which this page cannot see from pasted text. Remove the header block before pasting.

security.txt generator

email addresses become mailto:; also https: and tel: URIs
UTC date-time; defaults to one year ahead (less one day, as RFC 9116 asks for under a year)
comma-separated language tags, written once
https:, dns: or openpgp4fpr: URI of a key, never an email address
